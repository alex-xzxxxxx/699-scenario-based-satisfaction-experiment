## T13 and T14 — the execution harness

| Component | File | Does |
|---|---|---|
| Step helpers | `harness/runner/steps.py` | 16 reusable actions; a scenario names them |
| Scenario format | `harness/runner/scenario.py` | Loads and validates the Table B1 fields (FR1) |
| Runner | `harness/runner/runner.py` | Executes one scenario against one version |
| Evidence collector | `harness/evidence.py` | Writes one bundle per run under an anonymized id |

Scenarios are data. Adding one in T15 means writing YAML, not Python.
`python -m harness.runner.runner --check` validates the whole library —
required fields, legal category and severity, every step naming a helper that
exists — without a browser.

### The runner does not decide anything

Suite A and suite B assert. Scenarios are executed and *then judged*. Every
step helper performs an action and records what it saw; none of them rules on
whether the scenario was satisfied. A runner that decided for itself would
leave the LLM judge and the human reference nothing to disagree about, and EQ2
would have no data.

A step that cannot be carried out — a missing element, a timeout — is recorded
and the run continues where it can. A scenario that could not be executed is
evidence about the version, not a broken experiment.

### Blinding is built into the collector

About 25 runs are judged blind by the student (T26), and that reference is what
EQ2 and EQ3 are measured against. So:

- run ids are random tokens, encoding nothing
- the version appears only in `data/run_manifest.jsonl`, never in a bundle
- captured text is scrubbed of version words and absolute paths before writing
- the manifest and the bulk evidence are not committed, so the mapping cannot
  sit beside the bundles in the repository

The last point was a real near miss. The manifest was committed on 17 November
and removed the same day. With three shakedown runs nothing was compromised,
but the same habit at the main run would have put the run-id-to-version map in
the repository next to the bundles it is supposed to be separate from.

### First evidence bundle

`records/W04/first-evidence-bundle/` holds the TSK-03 run: 11 steps, 5
screenshots, console log, network log, and the trace in both JSON and Markdown.
The JSON is what a judge receives; the Markdown is the same content for a
person to read.

Its substance, in the three captures:

> 4 task rows → *"Title is required."* → 4 task rows

Enough to judge from, short enough that 540 LLM calls fit a free tier and a
person can read 25 of them (D-009).
